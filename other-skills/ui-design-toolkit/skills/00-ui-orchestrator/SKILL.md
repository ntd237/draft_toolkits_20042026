# UI Design Orchestrator

## Language Protocol
- Respond in Vietnamese. Restate non-English requests in English first.
- Internal analysis in English; final response in Vietnamese.

## Trigger
Activates when the user requests end-to-end interface design, design system creation, UX wireframing/flows, responsive layout architecture, or multi-platform UI adaptation across Web Apps, Mobile Apps, Desktop Apps, Desktop Games, or Mobile Games, producing a structured `system_design.md`.

Skip for pure backend logic, database modeling, infrastructure/DevOps, or non-visual automation scripts.

## Workflow

### Phase 1: Context & Platform Analysis
**Objective**: Determine the exact product category, target platforms, and responsive scope before routing.

1. Classify the product category: SaaS, Admin Dashboard, E-commerce, Mobile Utility, Desktop Tool, Game HUD, or In-game Menu.
2. Identify the target platform matrix and input models:
   - Web App (SPA/SSR, High data density, Pointer/Keyboard)
   - Mobile App (iOS/Android, Touch, Safe area insets, Thumb zone)
   - Desktop App (Windows/macOS/Linux, Custom window chrome, Menu bar, Context menu)
   - Game Desktop (PC/Console, 16:9/21:9 Ultrawide, HUD anchors, Gamepad focus ring)
   - Game Mobile (Landscape/Portrait, Dual thumb touch zones, Semi-transparent HUD, Haptics)
3. Determine required responsive scope: Mobile (<768px), Tablet (768-1024px), PC (>1024px), Ultrawide (>1920px).
4. Establish aesthetic posture and constraints (e.g., Vietnamese typography support, Dark mode, token systems).

### Phase 2: Specialist Routing & Execution Plan
**Objective**: Construct an execution plan and dispatch tasks to specialist skills using the routing matrix.

1. Reference `references/workflow-routes.md` to select the execution route:
   - Greenfield / Full design: Standard sequential pipeline `01` → `02` → `03` → `04`.
   - Narrow scope: Trigger the matching specialist skill directly.
2. Present a brief execution summary to the user before deep implementation:
   - **Target Platform(s)**: [Web / Mobile / Desktop / Game]
   - **Responsive Scope**: [Mobile / Tablet / PC]
   - **Triggered Skills**: List planned skills and specific goals.
3. Coordinate handoff data across skills:
   - `01-ux-flow-architecture`: Supplies sitemap, user task flows, error paths, and structural wireframes.
   - `02-ui-design-system`: Supplies design tokens (60-30-10 palette, Vietnamese typography), 6-state component specifications.
   - `03-ui-platform-responsive`: Supplies responsive breakpoint matrix and platform-specific UX recipes.
   - `04-ui-ux-qa-review`: Conducts WCAG 2.2 AA audit, usability heuristics check, and Vietnamese typography stress testing.

### Phase 3: Specification Synthesis & Delivery
**Objective**: Consolidate all design decisions into the standardized system_design.md deliverable.

1. Aggregate outputs into `docs/ui-design/system_design.md` following the template in `references/system_design_spec.md`.
2. Verify cross-system coherence: Ensure components use defined tokens, respect layout breakpoints, and follow platform recipes.
3. Present the final design specification for user approval before handoff to frontend engineering or implementation.

### Phase 4: Sample Interface Consent Gate
**Objective**: Offer optional static sample generation after the specification is approved.

1. After the user approves `system_design.md`, ask: "Bạn có muốn tạo giao diện mẫu (HTML/CSS/JS) dựa trên đặc tả system_design.md không?"
2. If the user agrees, route to `05-ui-example-generator` to generate sample pages from the spec into `docs/ui-design/examples/`, then report the created files to the user.
3. If the user declines, end the workflow at the approved specification without generating any additional files.

## Output Format
Unified system design specification file at `docs/ui-design/system_design.md` containing:
1. Product & Platform Context
2. UX Architecture & Flows (including error/recovery paths)
3. Design Tokens (60-30-10 Colors, Vietnamese Typography, Spacing, Radius, Elevation)
4. Component Specifications (All 6 interactive states)
5. Responsive Layout Matrix (Mobile/Tablet/PC) & Platform Recipes (Web/App/Game)
6. QA & Accessibility Sign-off

Optional follow-up (user opt-in only): static sample interface pages generated by `05-ui-example-generator` under `docs/ui-design/examples/`.

## Don'ts
- Do not skip the platform classification step before generating layout or component specifications.
- Do not use arbitrary hex colors or pixel numbers (magic numbers); enforce semantic design tokens.
- Do not produce user flows that lack error/recovery paths or empty/zero states.
- Do not bypass `04-ui-ux-qa-review` before finalizing the design deliverable.
- Do not generate sample interfaces without explicit user consent at the Phase 4 gate.

## Quality Checklist
- [ ] Target platform(s) and responsive scope explicitly declared
- [ ] Execution plan matches the task scope in `references/workflow-routes.md`
- [ ] Deliverable conforms to the structure in `references/system_design_spec.md`
- [ ] Color system follows 60-30-10 balance with verified Light/Dark contrast
- [ ] Typography specifies safe line-height (1.4-1.6) protecting Vietnamese diacritics
- [ ] All interactive components define all 6 required states
- [ ] Platform constraints (mobile safe areas, desktop chrome, game HUD anchors) are explicitly addressed
- [ ] `04-ui-ux-qa-review` sign-off confirms WCAG 2.2 AA and usability heuristics compliance
- [ ] Phase 4 consent question asked after spec approval; sample generation only on explicit opt-in
